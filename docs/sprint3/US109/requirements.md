# US109 — Requirements (Sprint 3)

## User story

As a PO, I want final simulation report generated by a dedicated thread, for consistent output and Java backoffice integration.

---

## Functional requirements

1. **R1 — Thread-safe aggregation**  
   `simulation_report_t` protected by mutex for concurrent writes.

2. **R2 — Structured CSV**  
   Metrics, flights, and violations sections parseable by Java.

3. **R3 — validation_result**  
   Global PASS/FAIL derived from violations and critical failures.

4. **R4 — Report thread**  
   Violations recorded by report thread (US107), not synchronously in detection.

5. **R5 — Dual output**  
   `.txt` (human) and `.csv` (machine) files.

6. **R6 — Configurable directory**  
   `FS_REPORTS_DIR` override for tests and Java.

---

## Acceptance criteria

| ID | Criterion |
|----|-----------|
| AC1 | CSV parsed by `SimulationReportParserTest` without errors. |
| AC2 | `collision` → non-empty violations section. |
| AC3 | `all_valid` → `validation_result,PASS`. |
| AC4 | US111 generates summary from CSV. |
| AC5 | No data corruption with safety + report threads active. |
